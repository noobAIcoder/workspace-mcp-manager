# P7.1 — Stateless Client Compatibility Status

Status: **IMPLEMENTATION QUALIFIED — ATOMIC CODING READY; CROSS-SESSION COMMAND HANDLES SESSION-SCOPED**

## Corrected interpretation

The original P7.1 report treated loss of `Mcp-Session-Id` continuity across
ChatGPT tool invocations as a hosted tunnel/control-plane defect. That
interpretation is superseded.

Comparison with other working coding-tools instances demonstrated that
`default_cwd` commonly resets between ChatGPT tool calls without preventing
ordinary repository work. More importantly, the protocol direction after MCP
`2025-11-25` is stateless: cross-call state should be represented by explicit
server-minted handles rather than by requiring one protocol session to survive
all calls.

The relevant qualification question is therefore:

```text
Can ordinary atomic tools complete without mutable protocol-session state?

If a tool returns an explicit process/output handle, can a fresh MCP session
use that handle?
```

## What passes

The following capability class is fully usable without requiring one persistent
MCP protocol session:

```text
repository discovery and metadata
read_file / list_files / search_text
apply_patch
Git inspection
bounded exec_command
Node/npm/pnpm repository commands that finish within one invocation
explicit path/cwd/workdir operation
```

This is the ordinary coding-readiness class used by `ElectroCADCodingTools` and
other coding-tools instances.

## Remaining limitation

`coding-tools-mcp 0.2.2` currently scopes the explicit process/output handles
returned by `exec_command` to the creating MCP protocol session.

Therefore a client that starts a fresh MCP session for its next tool invocation
cannot currently perform:

```text
exec_command -> write_stdin on a later call
exec_command -> kill_session on a later call
output_ref   -> read_output on a later call
```

The observed response is `SESSION_NOT_FOUND`.

This is **not** evidence that ordinary MCP coding requires protocol-session
persistence, and it is no longer classified as a hosted tunnel fault.

## Desired future coding-tools model

If cross-call interactive process control is required, coding-tools should make
its server-minted process/output handles usable independently of the transient
MCP protocol session while retaining strict instance/workspace isolation,
unguessable handles, bounded TTL/resource counts, and explicit cleanup.

`default_cwd` should remain convenience-only; clients should prefer explicit
`cwd`, `workdir`, or path arguments.
