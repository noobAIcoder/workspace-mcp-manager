# P7.1 — Tunnel-Backed MCP Session Continuity Status

Status: **LOCAL STACK QUALIFIED — HOSTED CONNECTOR CONTINUITY FAIL OBSERVED**

## Reproduced finding

Through `ElectroCADCodingTools`, consecutive ChatGPT tool calls do not retain
session-scoped coding-tools state:

```text
set_default_cwd("docs") -> docs
get_default_cwd()        -> .
```

Persistent command handles created by `exec_command` likewise become
unavailable to subsequent ChatGPT calls (`SESSION_NOT_FOUND`). The same
default-cwd reset was independently observed through `LeadBotCodingTools`, so
the behavior is not ElectroCAD-specific.

Two consecutive tunnel-backed `server_info` calls reached the same ElectroCAD
deployment identity but reported different per-MCP-session runtime directory
suffixes, consistent with a fresh MCP session being created for each ChatGPT
tool invocation.

No raw `Mcp-Session-Id` values are retained in this report.

## Layer 1 — direct local Streamable HTTP MCP

Against ElectroCAD's manager-authoritative local MCP endpoint, one explicit
`Mcp-Session-Id` was reused for:

```text
initialize
notifications/initialized
set_default_cwd("docs")
get_default_cwd()
exec_command(tty cat)
write_stdin
read_output
kill_session
DELETE
```

Observed result:

```text
coding-tools-mcp: 0.2.2
protocol: 2025-11-25
MCP session: PASS
default_cwd continuity: PASS
command-session continuity: PASS
session DELETE cleanup: PASS
```

Therefore `coding-tools-mcp`'s local session store is not the source of the
reported continuity loss.

## Layer 2 — installed tunnel-client local dev proxy

Installed client:

```text
tunnel-client 0.0.11+8d55683eeef80bc5e360d95abf4692454fafc615
```

`tunnel-client dev proxy` was pointed at the same ElectroCAD local MCP endpoint.
The same sequence through the proxy preserved:

```text
default_cwd continuity: PASS
exec_command -> write_stdin: PASS
read_output: PASS
kill_session: PASS
```

The local dev-proxy ingress returned HTTP 501 for final MCP DELETE/session
termination. This is recorded separately and does not invalidate the positive
state-continuity result.

The local tunnel-client forwarding path is therefore cleared for the reported
state-loss defect.

## Current fault boundary

```text
direct coding-tools MCP                     PASS
local tunnel-client dev proxy continuity    PASS
hosted tunnel/control-plane + connector     FAIL observed
```

Current fault domain:

```text
HOSTED_TUNNEL_CONTROL_PLANE_OR_CHATGPT_CONNECTOR
```

No manager or coding-tools workaround should broaden MCP session state across
unrelated sessions. The correct upstream behavior is to preserve/reuse the
active MCP session identifier for a logical connector session.
