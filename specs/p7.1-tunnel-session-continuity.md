# P7.1 — Stateless Client Compatibility and Cross-Call Resource Handles

## Status

Normative qualification specification. This revision supersedes the original
P7.1 assumption that a ChatGPT connector must preserve one `Mcp-Session-Id`
across successive tool invocations.

## Objective

Qualify coding-tools for clients that may invoke every tool call through a
fresh MCP protocol session while preserving the distinction between:

```text
ordinary atomic coding operation
    vs
explicit cross-call server resource handle
```

Protocol-session persistence is not an ordinary coding-readiness requirement.
The manager MUST instead determine whether tools whose result explicitly
contains a follow-up handle can use that handle from a fresh MCP session.

This is also the forward-compatible model: the MCP specification direction
after revision `2025-11-25` removes protocol-level sessions and requires
cross-call state to use explicit server-minted handles passed as ordinary tool
arguments.

## Capability classes

### Atomic/stateless operations

The following capability class MUST NOT depend on mutable MCP-session state:

```text
read_file / list_files / search_text
apply_patch
git status/diff/log/show/blame
bounded exec_command that completes in one invocation
other tools whose complete input and result fit one tool call
```

Path-sensitive tools SHOULD receive explicit `path`, `cwd`, or `workdir`
arguments. `set_default_cwd` is convenience state only and MUST NOT be required
for coding readiness.

### Explicit cross-call resources

Tools MAY return opaque server-minted handles such as:

```text
exec_command -> session_id
exec_command -> output_ref
```

If the server advertises follow-up tools for those handles, qualification MUST
classify whether each handle is:

```text
cross_session
session_scoped
partial_or_unavailable
```

`cross_session` means a new MCP protocol session can use the explicit handle.
`session_scoped` means the handle works only while the creating MCP protocol
session is retained.

A `session_scoped` classification is a product limitation for clients that use
fresh MCP sessions per call, but it MUST NOT make ordinary atomic coding
operations unready.

## Isolation invariants

Cross-session resource support MUST NOT make resources globally enumerable or
implicitly shared. A future implementation that supports cross-session handles
MUST preserve:

```text
opaque unguessable handles
instance/workspace ownership
bounded retention and TTL
bounded process/output resource counts
explicit kill/cleanup behavior
no cross-instance handle reuse
no credential material in handles or evidence
```

`default_cwd` MUST NOT be promoted to process-global or instance-global mutable
state merely to emulate protocol-session persistence.

## Public manager contract

Primary command:

```text
workspace-mcp-manager instance client-compatibility <instance-id>
```

Backward-compatible alias:

```text
workspace-mcp-manager instance session-continuity <instance-id>
```

The alias MUST return the same projection and MUST NOT imply that protocol
session continuity is a readiness requirement.

## Local qualification sequence

For the currently deployed `2025-11-25` coding-tools protocol, the manager MAY
use protocol sessions as a diagnostic mechanism.

### Session A — prove server-local functionality

```text
initialize A
notifications/initialized A
set_default_cwd(<known subdirectory>)
get_default_cwd -> same value
exec_command(tty cat) -> process session_id + output_ref
write_stdin(process session_id)
read_output(output_ref)
```

This proves that the server's own session-local process machinery works.

### Session B — classify explicit handle scope

Without terminating session A:

```text
initialize B
notifications/initialized B
get_default_cwd
write_stdin(process session_id from A)
read_output(output_ref from A)
kill_session(process session_id from A)
```

Expected interpretation:

```text
fresh get_default_cwd resets
    -> session_scoped_optional; not a failure

write/read/kill all succeed with A handles
    -> command_handles = cross_session

write/read/kill return SESSION_NOT_FOUND for A handles
    -> command_handles = session_scoped
```

If session B cannot kill a session-scoped process, session A MUST perform
cleanup before protocol-session cleanup.

## Versioned projection

```text
client_compatibility_projection_version = 1
session_continuity_projection_version = 2  # backward-compatible field
```

Conceptual result for coding-tools 0.2.2:

```json
{
  "ok": true,
  "client_compatibility_projection_version": 1,
  "session_continuity_projection_version": 2,
  "instance_id": "electrocad",
  "scope": "local_mcp",
  "server": {"version": "0.2.2", "protocol": "2025-11-25"},
  "atomic_coding_ready": true,
  "protocol_session_persistence": "not_required_for_atomic_operations",
  "session_local_state": {
    "mcp_session": "passed",
```

## Readiness interpretation

The manager MUST interpret:

```text
atomic_coding_ready=true
command_handles=session_scoped
```

as:

```text
ordinary coding readiness              PASS
bounded exec_command                    PASS
protocol-session persistence            NOT REQUIRED
cross-call interactive process control  LIMITED
```

The limitation MUST NOT be attributed to the hosted tunnel/control plane merely
because a client chooses a fresh MCP session per tool call.

## Tunnel-client control

`tunnel-client dev proxy` SHOULD repeat the same client-compatibility sequence.
Its purpose is to prove that forwarding preserves the server's capability
classification, not to require one long-lived MCP session.

For a session-scoped coding-tools server the expected result through the local
proxy is still `session_scoped`.

## Evidence safety

Qualification evidence MAY include:

```text
tunnel-client version/git SHA
coding-tools-mcp version
MCP protocol version
short non-secret session fingerprints
atomic readiness
session-local state status
cross-session handle classification
```

It MUST NOT contain:

```text
control-plane API keys
GitHub credentials
raw Mcp-Session-Id values
raw process handles beyond bounded ephemeral qualification use
authorization headers
credential-bearing environment dumps
```
